## この記事でやりたいこと

Amazon SNS の `email` サブスクリプションで送られる通知メールには **Unsubscribe（配信停止）リンク**が含まれます。

ただし運用上、

- 誰でもメール本文のリンクを踏めば解除できる状態は避けたい
- 意図せず解除されたくない（監視通知・監査通知など）

というケースがあり、SNSには **UnsubscribeにAWS認証を要求する**設定があります。

本記事では、この設定を **“Unsubscribeリンクを無効化（=メールだけで解除できない状態）”** と表現し、  
その **設定手順と確認方法**をまとめます。

> ⚠️ 注意  
> SNS の `email` 通知メールから **Unsubscribeリンク自体を完全に消す**ことはできません。  
> ここで扱うのは「リンクを踏んでも“解除完了”にならない（AWS 認証が必要になる）」状態です。

---

## 前提

- 対象: Amazon SNS（Standard topic）
- プロトコル: `email`
- 実行環境: AWS CLI （CloudShellでOK）が使えること
- 権限: SNS 操作ができる IAM 権限（`sns:Subscribe`, `sns:ConfirmSubscription`, `sns:GetSubscriptionAttributes`, `sns:Publish` など）
- Unsubscribeリンクを無効化したいSNS Topicが既に存在している

---

## 全体の流れ

1. Unsubscribeリンクを無効化したいSNS Topicのサブスクリプションを削除する
2. Email サブスクリプションを新たに作成（確認メールが届く）
3. **確認メールの “Confirm subscription” はクリックしない**
4. サブスクリプションの確認に貼り付ける
5. 属性確認をする
6. テスト通知を送り、メール内 Unsubscribe を踏んで挙動確認

---

## 1. Unsubscribeリンクを無効化したいSNS Topicのサブスクリプションを削除する

今回error2を題材に説明します。
Unsubscribeリンクを無効化したいサブスクを選択して、削除してください。
例では1つしかありませんが、複数サブスクを登録している方はUnsubscribeリンクを無効化したいサブスクを適宜選択してください。

![スクリーンショット 2026-03-05 11.48.52.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/3839634/a55a8e86-13dd-4671-a533-64c8a1ec36a3.png)


## 2.Email サブスクリプションを新たに作成
先ほどサブスクを削除しましたが、同じ設定でまたサブスクを作成してください。

作成すると保留中の確認となります。確認済みにするための設定がとても重要です。
![スクリーンショット 2026-03-05 11.51.21.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/3839634/de722361-a9a5-4071-af31-00727657c0a4.png)

## 3. **確認メールの “Confirm subscription” はクリックしない**
先ほどのサブスク作成で登録したメアドにメールが届きます。

こんな感じのメールが届くので**Confirm subscription**を右クリックしてリンクのアドレスのみコピーしてください
![スクリーンショット 2026-03-05 11.53.58.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/3839634/1adcc09b-2869-4694-abd7-b7454dffa205.png)

## 4.サブスクリプションの確認に貼り付ける

これにより確認済みへと状態が変わります。
![スクリーンショット 2026-03-05 11.56.52.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/3839634/5f5dc2a2-26b8-4c25-9cb3-4bca8d0a2fd3.png)

## 5. 属性確認をする
本当にUnsubscribe リンク“無効化”になったのかCloudShellで確認します。
以下コマンドを実行してください。
対象サブスクのARNは対象サブスクを選択してコンパネから確認できます。

```
aws sns get-subscription-attributes  --subscription-arn 対象サブスクのARN
```

```
#こんな感じのやつがサブスクのARNです。
arn:aws:sns:ap-northeast-1:xxxxx:error2:xxxxxxxxxxxxxxxxx
```

コマンドを実行すると下記のように結果が出力されます。
ここで　ConfirmationWasAuthenticated = true
となっていればOKです。リンクがクリックでは解除されないようになります。

```
~ $ aws sns get-subscription-attributes  --subscription-arn arn:aws:sns:ap-northeast-1:xxxxx:error2:xxxxx
{
    "Attributes": {
        "SubscriptionPrincipal": "arn:aws:iam::xxxxx:role/aws-reserved/sso.amazonaws.com/ap-northeast-1/AWSReservedSSO_AdministratorAccess_xxxxxx",
        "Owner": "xxxxxx",
        "RawMessageDelivery": "false",
        "TopicArn": "arn:aws:sns:ap-northeast-1:xxxxx:error2",
        "Endpoint": "xxxxxx",
        "Protocol": "email",
        "PendingConfirmation": "false",
        "ConfirmationWasAuthenticated": "true",
        "SubscriptionArn": "arn:aws:sns:ap-northeast-1:xxxxx:error2:xxxxxx"
    }
}
```

## 6. テスト通知を送り、メール内 Unsubscribe を踏んで挙動確認
設定は完了していますが、まだ不安な方は実際にテストしてみましょう。

下記コマンドをCloudShellで実行してください
$TOPIC_ARNは対象のトピックARNに置き換えてください。

```
aws sns publish \
  --topic-arn "$TOPIC_ARN" \
  --message "SNS unsubscribe test"
```
下記のようなメールが届くかと思います。
リンクを思いっきり踏んでみてください
![スクリーンショット 2026-03-05 12.16.52.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/3839634/c977190d-0380-4b29-9948-fcbe373a421d.png)

解除されなくなりました!!!
これで誰が解除したのか犯人探しを社内でする必要がなくなります。
設定自体は簡単なのでぜひ試してみてね。
